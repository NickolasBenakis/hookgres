Webhooks from the Postgres you already run.

Hookgres signs, sends, retries and logs the webhooks your customers subscribe to. It's an open-source TypeScript library, so there are no extra servers, no queue to operate and no per-message bill.

Add Hookgres (https://hookgres.dev) to this project so we can send signed webhooks to our customers. First read https://hookgres.dev/llms.txt. Then install hookgres and pg, run migrate() on startup, start the delivery worker with a graceful shutdown, add API routes for customers to manage their webhook endpoints scoped to their tenant, and call send() inside our existing database transactions where events happen. Block private network addresses as the production guide describes.

Paste into Claude Code, Codex, Gemini CLI or Cursor.

$ npm install hookgres pg

One event, three customer endpoints, on the default retry schedule. Every attempt's status, response and timing is stored in your database.

One call to send. The rest is handled.

Hookgres writes the message and one delivery per subscribed endpoint, then a worker in your app signs each request, sends it, retries failures and records every attempt.

Getting started

app.ts
import { Hookgres } from "hookgres";

const hookgres = new Hookgres({ pool });
await hookgres.migrate();
hookgres.start();

// Your customer registers an endpoint
await hookgres.createEndpoint({
  tenantId: "acme",
  url: "https://acme.com/webhooks",
});

// Anywhere in your app
await hookgres.send({
  tenantId: "acme",
  eventType: "invoice.paid",
  payload: { invoiceId: "in_123", amount: 4200 },
});

Queued in your transaction. Sent only if it commits.

A hosted service sits outside your database, so a webhook can go out for an order that later rolled back. Hookgres writes the webhook in the same transaction as your data.

Workers claim deliveries with FOR UPDATE SKIP LOCKED, so you can run as many as you like.

Standard Webhooks signatures

HMAC-SHA256 per the open spec, checked against the official library in CI.

Built for multi-tenant apps

Every event goes only to one tenant's endpoints, filtered by event type.

Idempotency keys

Pass the same key twice and get the original message back, not a duplicate.

Replay

Re-send any finished delivery, with the same webhook-id so receivers can deduplicate.

Crash recovery

If a worker dies mid-request, its claim expires and another worker picks it up.

It's just tables

Query deliveries with SQL for dashboards, support and alerts. No vendor API to page through.

What your customers receive.

A JSON envelope and three signed headers. The webhook-id stays the same across retries. Delivery is at least once, so receivers deduplicate on it.

Verify in any language with the official Standard Webhooks libraries: JavaScript, Python, Go, Ruby, PHP, Rust, Java, C# and Elixir.
